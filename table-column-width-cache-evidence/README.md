# Reproduce the column-width cache measurements

The root report contains the conclusions and all primary result tables:

- [Full report](../TABLE-COLUMN-WIDTH-CACHE-PERFORMANCE.md)

## Recorded inputs

`baseline-node.rs`, `patched-node.rs`, `change.patch`, `Cargo.lock` and
`frame_probe.rs` are frozen measurement inputs. Their hashes are in
`source-metadata.json`. `measurement-manifest.json` records the original binary
and raw-data hashes plus the local environment. The exact compiled probe is
preserved, including its original formatting. The analysis and runner were
subsequently improved to pool identical cold fixtures, allow separate output
directories and prevent overwriting recorded samples; the original timing data
were not changed.

`frames.jsonl` contains all 208 frame processes, `memory.jsonl` all 96 memory
processes, and `lifecycle.jsonl` the lifetime assertions. `raw/` retains process
stdout/stderr. `summary.json` is generated by `analyze.py`. Original binaries are
retained locally in ignored `bin/`; they are approximately 126 MiB combined and
are not published in this archive. All four original headless/native executables total about 218 MiB. Bytecode, local-work.json and Cargo build JSON event streams are also omitted; binary hashes and build stderr remain available.

## Build and run

Requirements: Linux with glibc (`mallinfo2`, `/proc`), Python 3.12 or newer,
`taskset`, the repository's native build dependencies, DejaVu Sans and DejaVu
Sans Mono, and installed CJK fallback fonts. The recorded toolchain is Rust
1.98.0. Cargo uses `--offline --locked`, so the exact lockfile dependencies must
already be cached. Ensure the frozen baseline commit exists locally. CPU 4 must
be available; choose another `--cpu` if necessary and record that difference.

Run from the evidence worktree root, sequentially. Use the normal fork clone and shared Git object history described in the root README; the frozen baseline must exist locally. Use a disposable worktree because builds overwrite local build metadata. `prepare.py` restores the frozen
commit into a separate temporary directory using `git archive`, verifies all
frozen input hashes and does not modify the active checkout or `.git`. It adds
one empty feature to the temporary Base manifest solely to compile cache-field
introspection in the patched probe; production algorithms are selected by the
frozen source files. The build scripts use release library tests, avoiding the
unrelated existing Criterion benchmark target conflict.

```bash
python3 table-column-width-cache-evidence/prepare.py --work /tmp/gpui-column-reproduction/work
python3 table-column-width-cache-evidence/build.py baseline
python3 table-column-width-cache-evidence/build.py patched

python3 table-column-width-cache-evidence/run.py --suite frames --rounds 8 --cpu 4 --output-dir /tmp/gpui-column-reproduction/results
python3 table-column-width-cache-evidence/run.py --suite memory --rounds 8 --cpu 4 --output-dir /tmp/gpui-column-reproduction/results
python3 table-column-width-cache-evidence/run.py --suite lifecycle --rounds 1 --cpu 4 --output-dir /tmp/gpui-column-reproduction/results
python3 table-column-width-cache-evidence/analyze.py --input-dir /tmp/gpui-column-reproduction/results

table-column-width-cache-evidence/bin/patched table_column --nocapture --test-threads=1
```

Use a fresh results directory for each repetition. The runner refuses to
overwrite an existing suite. To recompute the committed/local original summary
without rerunning the benchmark:

```bash
python3 table-column-width-cache-evidence/analyze.py
```

## Interpretation

These are native-font, headless CPU draw measurements. Parsing occurs before
timing; no GPU presentation or real input dispatch is measured. The fixtures
exercise vertical page scrolling with horizontal-scroll table layout enabled.
The memory probe isolates retained tables after font/shape warmup; it is not a
long-running native application leak test. See the root reports for the cold
draw, control-group, large-table variance and RSS-retention limitations.

## Native follow-up

The follow-up adds 24 pairs ×240 frames for each large-table operation, using
the exact original binaries. See `followup-large/summary.json`: static redraw
saves 0.858 ms/frame (8.3%, 24/24 pairs faster); scroll saves 0.577 ms/frame
(5.7%, 23/24). Both original and new samples are retained.

```bash
python3 table-column-width-cache-evidence/analyze_followup.py --large table-column-width-cache-evidence/followup-large
```

Both native release executables have been compiled and run with hardware GPU
rendering after the user enabled approval-based escalation. The earlier
restricted-session failures in `native-environment-check.json` and
`native-startup-check/` are retained as resolved history. The native environment
is Wayland, RX 7900 XTX (RADV Mesa 26.2.1), 3840×2160 @170 Hz, scale 1.75;
matching KWin settings report VRR policy `Never`. No display setting was changed.
Keep the opened measurement window active and unobscured and do not resize it.
Use the same monitor refresh/scale for both variants and record the VRR setting.

Set `WIDTH_DISPLAY_HZ` below to the display's **actual configured refresh rate**;
60 is only an example. The full default suite (medium scroll, large redraw,
large scroll, wrap redraw) takes about 13 minutes at 60 Hz. Every process warms
up for 120 presents and records 600; each scenario uses eight alternating A/B
pairs. No CPU pinning is applied by default, preserving normal native-app
multicore scheduling. To start with only the previously inconclusive large
redraw, add `--case large --mode redraw` (about three minutes at 60 Hz).

Build both native variants first; compiled binaries are not included in this archive.

```bash
python3 table-column-width-cache-evidence/native.py build --work /tmp/gpui-column-native/work
WIDTH_DISPLAY_HZ=60
python3 table-column-width-cache-evidence/native.py run --refresh-hz "$WIDTH_DISPLAY_HZ" --output-dir /tmp/gpui-native-results-01
python3 table-column-width-cache-evidence/analyze_followup.py --native /tmp/gpui-native-results-01
```

`native.jsonl` records actual GPUI Present timestamps, per-frame draw/submit
costs, GPU, display, scale and focus. A lost-focus run is retained and stops the
suite instead of silently becoming a valid sample; rerun in a fresh output
directory. FPS uses actual present cadence, never inverse draw duration.
The analyzer reports P50/P95/P99 and the fraction of intervals exceeding 1.5
display periods; that is a long-interval measure, not confirmed dropped scanouts.
The root reports include the native result tables and their uncertainty.

### Recorded native batches

- `native-gpu-smoke/`: one short startup pair, excluded from formal statistics.
- `native-gpu-full/`: eight medium-scroll pairs, two large-redraw pairs and one
  interrupted large-redraw process with 397 inactive samples. All originals kept.
- `native-gpu-large-redraw/`, `native-gpu-large-scroll/`, `native-gpu-wrap/`:
  eight additional pairs each.
- `native-gpu-results/`: all 34 valid pairs (68 processes, 40,800 presents).
  The manifest records input hashes, focus exclusions and original locations;
  no timing-based sample selection.
- `native-gpu-environment.json`, `native-display-before.json`,
  `native-display-after.json`: GPU, monitor and scale evidence.

`assemble_native.py` records the original batch assembly and requires the original local binaries to verify their hashes. Those binaries are not published. The combined dataset is already provided for review; a new full uninterrupted native run can be analyzed directly without assembly.

To recompute only the existing combined summary:

```bash
python3 table-column-width-cache-evidence/analyze_followup.py --native table-column-width-cache-evidence/native-gpu-results
```
